# Building games with coding agents, 2025-2026

Scope: how solo devs and small teams ship games with Claude Code / Codex / Cursor, which engines fit the loop, and what that means for a 2D, dialogue-heavy, cozy Mandarin shop-counter game that needs an LLM + TTS backend and wants cheap reach.

Verification notes: "[walled]" = Medium post returned 403 to the fetcher; only the search-engine snippet was read. "[unverified]" = single secondary source, not checked against a primary. Everything else was read from the linked page.

## The 8-10 facts that matter most for this decision

1. **Practitioners converge on "text-serialized engines or the web" for agent work.** The most-cited first-hand Godot account (vblanco on HN, ~60k-line procedural RPG in Godot C#, three months) calls Godot "the best engine for AI work" because scenes and scripts are text and the engine is small enough to reason about; he rates Unreal as "too heavy on binary files" and Unity as closed-source so the agent "lacks reliable docs or a way to verify what the APIs do" ([HN thread](https://news.ycombinator.com/item?id=47404012)). A Japanese dev who built several Unity games with Claude Code and then rebuilt one in Godot found Godot "nearly no-code" and better-looking ([zizochan, June 2026](https://note.com/zizochan/n/n7a5c52819bba?hl=en)).
2. **Godot C# cannot export to the web.** Official docs: "Projects written in C# using Godot 4 currently cannot be exported to the web" ([Godot docs](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)). If you pick Godot and want a URL, you are on GDScript. Single-threaded web export (default since 4.3) needs no COOP/COEP headers and works on iOS/macOS; the threaded build does need those headers, which rules out ad networks and most third-party embeds.
3. **Godot headless cannot render.** `--headless` runs scripts and tests but every community MCP that returns screenshots either needs the editor open over WebSocket ([mkdevkit/godot-mcp](https://github.com/mkdevkit/godot-mcp), 173 tools, 4 commits) or runs the scene briefly through Movie Maker ([raising-heart/godot-mcp](https://github.com/raising-heart/godot-mcp)) or wraps it in Xvfb + ffmpeg ([godogen](https://github.com/htdt/godogen)). Browser stacks get screenshots, console and network logs from Playwright MCP with no such plumbing ([microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)).
4. **The shipped Codex game writeups are all browser games on web stacks.** OpenAI's own showcase (Void Explorer, TypeScript/Vite/Three.js) and the two community posts (a Phaser platformer; a TypeScript/Supabase/Vercel idle game in soft launch) are web. The idle-game author's key lesson: "tuning by feel alone hid compounding errors", fixed by making the economy pure deterministic functions with simulation tests ([community.openai.com, Aug 2026](https://community.openai.com/t/from-prototype-to-soft-launch-building-a-deterministic-ai-startup-idle-game-with-codex/1388893)).
5. **Agent-driven Phaser QA is already packaged.** game-creator's QA subagent runs build check, headless Chromium runtime check, gameplay replay, architecture check, and Playwright screenshot review, and the template exposes `render_game_to_text()` so the agent reads state as JSON instead of pixels ([PlayableIntelligence/game-creator](https://github.com/PlayableIntelligence/game-creator)). Phaser itself now ships a CLI that configures 76 agents including Claude Code and Codex ([phaser.io](https://phaser.io/cli/agents.md)). Phaser 4.0 shipped 10 April 2026, 4.1 on 30 April ([phaser.io/download](https://phaser.io/download/phaser4)).
6. **The failure mode everyone reports is drift at scale, not first-draft quality.** zizochan: as projects grew, "fine-grained corrections became hard to describe", code "became long and repetitive", refactors were reverted. vblanco: don't one-shot; document core systems and point CLAUDE.md at the engine source so the agent can check itself. HN also notes text `.tscn` files slow down past ~1 MB (switch to binary `.scn`), which erodes Godot's text advantage for big scenes.
7. **Two agents on one repo is a solved, documented pattern.** One worktree per agent (`git worktree add ../app-x -b x`), shared `CLAUDE.md` + `AGENTS.md`, rules "never git stash" (stash is shared across worktrees) and "update HANDOFF.md at end of each unit", `strictPort` in Vite so parallel dev servers fail loudly, and cross-review via `codex review --uncommitted` / `git diff | claude -p "Review..."` ([dev.to, Oct 2026](https://dev.to/offrun/running-claude-code-and-codex-in-parallel-on-one-repo-git-worktree-gotchas-and-cross-review-41eg)). The Codex desktop app (Feb 2026) manages worktrees natively [unverified].
8. **Web reach is real but it is an ad-funded, short-session, top-of-funnel channel.** Poki's 2026 study (n=2,000 players, 400 devs, US/UK): 100M+ monthly players on Poki alone, typical session 11-20 minutes, 62% have downloaded or bought a game after first playing it on web, 46% of mobile web players quit a game because it loaded too slowly, 58% play web games because they are free ([poki.com](https://poki.com/blog/state-of-web-gaming-report-2026)). Meanwhile the median Steam indie earned about $249 gross in 2025 ([80.lv](https://80.lv/articles/analysts-report-drop-in-game-revenue-on-steam-despite-growing-number-of-releases)).
9. **LLM and TTS costs are trivial if content is shared and pre-rendered, and still small if live, as long as the cheap tier is used.** Claude Haiku 5.5 is $0.10/M input, $0.50/M output; Batch API is 50% off (Anthropic pricing via the bundled claude-api skill, cached 2026-10-06). Neural Mandarin TTS lists at roughly $15/M characters (Azure standard neural, third-party quotes) to $100/M (MiniMax speech-02-hd, official). A 20-character Mandarin line costs about $0.0003 to synthesize once; Cloudflare R2 serves it with zero egress ([r2-calculator.cloudflare.com](https://r2-calculator.cloudflare.com/)).
10. **Policy and disclosure are now part of the landscape.** Claude Code 2.1.314 (30 Oct 2026) added a system-prompt rule against recreating specific existing games; original games and genre work are fine ([madrobot.blog](https://madrobot.blog/2026/10/30/claude-code-rule-no-existing-game-recreations/)). Steam requires an AI disclosure; WonderLang Mandarin Chinese (Steam, Feb 2026, 6 reviews, £20.99) discloses AI reference images redrawn by artists ([Steam](https://store.steampowered.com/app/4028830/WonderLang_Mandarin_Chinese/)). The community "Claude & Codex Coding Jam 2026" allowed AI code but banned AI art; 16 of 20 entries were browser-playable ([itch.io](https://itch.io/jam/claude-code-jam)).

## 1. Shipped and notable agent-built games

**Godot.** vblanco (HN, March 2026): procedural open-world RPG "spiritual remake of Daggerfall", ~60k lines of Godot C#, 60 fps on Steam Deck, three months, $100/month Claude plan ("the $20 plan is a trial"). Workflow: incremental steering, written docs for core systems, CLAUDE.md pointing at the Godot source tree so the agent verifies APIs ([HN](https://news.ycombinator.com/item?id=47404012)). The parent Show HN was godogen, an orchestrator + fresh-context executor skill pair that builds Godot/Bevy/three.js games from a prompt and judges from Xvfb screen recordings; commenters found output Pong/Snake-level with frequent mid-pipeline failures ([godogen](https://github.com/htdt/godogen), 7.3k stars). zizochan (June 2026) built three Godot games (quiz Pong, a kanji-only pseudo-FPS, a Tetris with yandere dialogue) with no supplied assets ([note.com](https://note.com/zizochan/n/n7a5c52819bba?hl=en)). The Mormon Trail RPG devlog (Godot 4, GDScript) describes moving from pasting chat code to Claude Code writing files directly, and advises not making the agent hold the whole game in one conversation ([itch devlog](https://russperry.itch.io/the-mormon-trail-rpg/devlog/1133249/dec-26-devlog)) [snippet only].

**Web / Phaser / Three.js.** OpenAI's "Building games with Astra" (Thomas Ricouard, Sep 2026): Void Explorer, procedural space game, TypeScript/Vite/Three.js/WebGPU; the agent proposed architecture, inspected game state, reproduced issues, and ran "journey tests" (travel, land, walk, save, take off) ([mirror](https://www.plushcap.com/content/openai/blog/openai-building-games-with-astra); original 404 at fetch time). Community Codex Phaser platformer (Feb 2026): author never read the Phaser API, used SKILL.md as a table of contents, DESIGN-DOCUMENT.md and PROGRESS.md as memory, Playwright plus an evaluation checklist for verification; what broke was UX (WASD-only controls, unreadable pixel font) ([community.openai.com](https://community.openai.com/t/show-2d-game-built-using-codex-and-agent-skills-zero-code/1374319)). AI Model Foundry idle game (Aug 2026): TypeScript, Supabase, Vercel, Stripe; Codex did implementation, Supabase/Vercel integration, security review, tests, deployment; offline progress initially trusted browser timestamps and a playtester broke it on day one ([community.openai.com](https://community.openai.com/t/from-prototype-to-soft-launch-building-a-deterministic-ai-startup-idle-game-with-codex/1388893)). Platypus's AFTER LIGHT dev log is Unity + Codex + Blender MCP ([community.openai.com](https://community.openai.com/t/ai-game-studio-dev-log-by-platypus/1397035)) [snippet only].

**Steam.** Catvivors (roguelite auto-battler, Early Access) is described by its developer as built with Claude Code as main co-pilot ([Medium](https://pchojecki.medium.com/ai-helped-me-solo-dev-a-game-on-steam-f84a2425be10)) [walled; Steam page confirms Early Access but not the engine]. "12 Months of Unity Dev with Claude Code" (Dino Card Hunt) exists as YouTube videos with a wishlist link ([YouTube](https://www.youtube.com/watch?v=lf57tKke_XA)) [unverified]. Mr. Phil's Substack (July 2025) is the cautionary tale: Claude struggled with Godot "quirks", recommended MonoGame, then Zig+SDL2 "to suit its own strengths"; the author lost progress on each switch ([Substack](https://mrphilgames.substack.com/p/how-i-use-claude-like-a-junior-dev)).

**Other.** XDA's Captain Hat is a Pygame platformer by Sonnet 4.6 in a weekend; verification was "play it and compare screenshots" ([XDA, Mar 2026](https://www.xda-developers.com/i-vibe-coded-a-fully-functional-game-with-claude-code-and-it-doesnt-look-vibe-coded-at-all/)). No Anthropic-run game jam or official game showcase was found; the only jam is the community itch one above.

## 2. Engine fit for agentic coding

| Engine | Agent can build/run/test without a human in an editor? | Screenshots | Hot reload | Notes |
|---|---|---|---|---|
| Godot 4 GDScript | Yes: text `.tscn`/`.gd`, `godot --headless --import`, GUT/gdUnit4 headless, `--export-release` CLI | Only with editor open (MCP) or Movie Maker/Xvfb | Editor-bound | Best non-web fit. Web export: GDScript only, single-thread default, WebGL2; Safari warnings; ~5 MB Brotli / 9 MB gzip empty build [unverified, vendor table] |
| Godot 4 C# | Same as above for native | Same | Same | **No web export.** vblanco's choice for a native RPG |
| Unity | Needs editor; domain reloads stall loop; YAML scenes but editor-only tasks (Animator, prefab wiring) | Via Unity-MCP ([IvanMurzak/Unity-MCP](https://github.com/IvanMurzak/Unity-MCP), [mcp-unity](https://github.com/codergamester/mcp-unity)) | Editor | Practitioners who tried both moved to Godot; a 2026 tutorial admits MCP ecosystem is "younger, setup varies" ([aiforanything](https://aiforanything.io/blog/claude-code-unity-game-development-tutorial-2026)) [secondary] |
| Unreal | Blueprints are binary; MCP plugins serialize graphs ([UnrealMasterAI](https://jaguarcode.github.io/UnrealMasterAI), paid [ClaudeUnreal](https://echoulen.github.io/claude-unreal/)) | Via plugins | Editor | No first-hand solo success story found; wrong tool for a 2D dialogue game |
| Phaser 3/4 | Yes: Vite dev server, Playwright, headless Chromium | Playwright MCP, free | Vite HMR | Official agent CLI; game-creator QA pipeline; `window.__TEST__` state hooks; Phaser 4 is a renderer rewrite, so Claude's Phaser 3 priors may be stale (ground it with docs) |
| PixiJS / Three.js / R3F | Yes, same tooling | Same | Vite HMR | Three.js TSL "rapidly shifting" causes hallucination unless grounded [Medium survey, walled]. [pixi-cjk](https://github.com/huang-yuwei/pixi-cjk) exists because canvas text needs CJK line-break help |
| Bevy | cargo build/test headless; MCP exists ([bevy-agent](https://docs.rs/bevy-agent), [PyBevy](https://pypi.org/project/pybevy/)) | Via MCP | Slow compiles | Breaking changes every release trip the model; godogen supports it but output is weak |
| LÖVE | CLI runnable, Lua | Manual | No | No agent writeups found |
| Ren'Py | Text scripts; [renpy-mcp](https://github.com/fracturedring/renpy-mcp) (74 tools, browser editor) | Via MCP | Partial | Good for pure VN; weak for shop/inventory systems and web distribution |
| Plain React/DOM (+ a canvas layer for sprites) | Yes: Vite, Vitest, Playwright snapshot = accessibility tree, agent reads real text not pixels | Playwright MCP | Vite HMR | Strongest agent priors of any stack; CJK wrapping (`line-break: strict`), IME, fonts, per-word tap targets, screen readers are free |

Specific practitioner reports: GUT needs a clean `--headless --import --quit` pass before tests so `class_name` scripts register, and leak-check lines can produce a non-zero exit ([Medium](https://medium.com/@kpicaza/ci-tested-gut-for-godot-4-fast-green-and-reliable-c56f16cde73d)) [snippet]; gdUnit4 needs `--ignoreHeadlessMode` because UI input fails headless ([gdUnit4 discussion](https://github.com/godot-gdunit-labs/gdUnit4/discussions/157)); [godot-runtime-test](https://github.com/khirsahdev/godot-runtime-test) was built specifically so Claude Code/Cursor can assert on scene properties via CLI. For Godot, [cc-godot](https://github.com/Zate/cc-godot/wiki) and [gdscript-lsp](https://purplejelly.itch.io/gdscript-lsp) feed the agent diagnostics from Godot's LSP.

## 3. Dev-loop specifics

**Visual verification.** The browser pattern: Playwright MCP (`claude mcp add playwright -- npx @playwright/mcp@latest`, `--headless`), `browser_snapshot` for structure and `browser_take_screenshot` for look, plus `browser_console_messages` ([playwright-mcp](https://github.com/microsoft/playwright-mcp)). Playwright's own README says CLI + skills is more token-efficient than MCP for high-throughput agents. For canvas games add a test hook: `window.__TEST__ = {ready, state(), commands}`, `?test=1&seed=42`, seeded RNG, frozen time, fixed viewport, and only diff screenshots at known-stable frames ([phaserjs skill notes](https://skills.sh/chongdashu/phaserjs-oakwoods/playwright-testing)). game-creator's `render_game_to_text()` is the same idea. For Godot, the loop is check_scripts -> run_project (headless, read output) -> capture_screenshot (Movie Maker) per raising-heart's plugin skill, or editor-open screenshots with mkdevkit's server.

**Automated playtests.** OpenAI's Void Explorer ran "journey tests" (travel, land, walk, save, take off). The idle game encoded its economy as pure functions with simulation tests. The lesson across both: make game rules deterministic data + pure functions so the agent can test without rendering; keep rendering a thin layer.

**Content as data.** Batch-generated dialogue shipped as JSON blobs is the pattern recommended for cost ([sorceress.games](https://sorceress.games/blog/script-an-ai-dialogue-generator-game-npc-pipeline-2026)) [secondary]. The Codex Phaser post used DESIGN-DOCUMENT.md + PROGRESS.md as the agent's memory; Mr. Phil used PLAN.md regenerated each morning.

**Two agents, one repo.** From the dev.to post: one worktree per agent beside the repo; Claude Code has `-w`/`--worktree`, Codex uses plain git; copy `.env` minus PORT and assign a free port per worktree; never `git stash` (shared across worktrees, one agent can pop another's); `git worktree remove` not `rm -rf`; `strictPort: true`; `HANDOFF.md` updated at the end of each unit; reviewer agents only report, never edit; separate `CLAUDE_CONFIG_DIR` / `CODEX_HOME` per login. Claude Code docs: project config and auto-memory are shared across worktrees of one repo ([code.claude.com worktrees](https://code.claude.com/docs/en/worktrees.md)). Godogen writes both `CLAUDE.md`+`.claude/skills/` and `AGENTS.md`+`.agents/skills/` from one source, which is the sane way to keep two instruction files in sync. This project's "one ticket per branch" convention maps directly onto one worktree per ticket per agent.

## 4. Dialogue and narrative tooling

- **ink / inkjs.** inkjs is the official JS port, zero-dependency, works in browsers and Node, usually one major version behind ink ([inkle/inkjs](https://github.com/inkle/inkjs)). ink passes text through as Unicode strings and leaves layout to the host, so CJK wrapping, per-word spans and ruby/pinyin are the renderer's job: trivial in DOM, needs [pixi-cjk](https://github.com/huang-yuwei/pixi-cjk)-style kinsoku handling on canvas. ink's tag syntax (`# audio:line_042`) is the natural place to attach a pre-rendered audio id. No CJK-specific issues found in the ink trackers, but also no shipped-Chinese-game writeup found.
- **Yarn Spinner.** Official Godot C# integration (4.1+), GDScript integration is alpha and needs 4.6 ([YarnSpinner-Godot-GDScript](https://github.com/YarnSpinnerTool/YarnSpinner-Godot-GDScript)); localization goes through CSV -> Godot `.translation`; the line presenter has word-by-word reveal but not per-word interaction ([docs](https://docs.yarnspinner.dev/yarn-spinner-for-godot/godot-gdscript)). Inline markup (`[calm]...[/calm]`) could carry per-word annotations. Note the C#-only stable path collides with "no C# on web."
- **Godot RichTextLabel.** Per-word tap is doable: wrap each word in `[url=id]`, connect `meta_clicked` (string payload; use `push_meta` for structured data), `meta_hover_started` for hover ([Godot docs](https://docs.godotengine.org/en/latest/classes/class_richtextlabel.html)). Godot 4 falls back to OS fonts for missing CJK glyphs, so bundle a font; `Word Smart` autowrap is word-based and needs testing on spaceless text ([uhiyama-lab](https://uhiyama-lab.com/en/notes/godot/japanese-font-richtextlabel/)). Dialogic 2: no CJK-specific reports found either way.
- **Custom JSON.** All agent-built dialogue systems found used their own JSON. For LLM-generated content this is simplest: one schema, validated with Zod/JSON Schema, which the agent can also unit-test. Segment Mandarin into word tokens at generation time (the LLM or jieba) and store `{hanzi, pinyin, gloss, audio_id}` per token so the UI never has to segment.

## 5. Backend patterns for LLM content

**Live vs batch.** The vendor post on dynamic NPCs (May 2026) estimates GPT-4o-mini at $2-5/day for 1,000 daily players × 5 NPCs, DeepSeek V3 at $0.50-1/day, with caching, 10-exchange windows, and streaming ([dev.to](https://dev.to/maximilian32541spec/how-we-built-dynamic-npc-dialogue-with-llms-lessons-from-early-access-4bfe)) [vendor]. Multiple guides push pre-generation to JSON for anything that many players will see and reserve live calls for truly personal responses ([theneuralbase](https://theneuralbase.com/ai-for-gaming/learn/beginner/cost-scaling-with-players/)) [secondary]. Academic reports note LLM NPCs leaking information early and lacking distinct personality ([CESCG 2025](https://cescg.org/wp-content/uploads/2025/04/A-Quest-for-Information-Enhancing-Game-Based-Learning-with-LLM-Driven-NPCs-2.pdf)), which argues for a reviewed batch pipeline for a learning game where the Mandarin must be correct.

**Worked numbers (Anthropic list prices, Haiku 5.5 $0.10/$0.50 per MTok, Batch 50% off).** One customer exchange ≈ 600 input + 150 output tokens ≈ $0.00014 live, $0.00007 batched. Shared content (a nightly batch of, say, 2,000 new lines for all players) costs cents per night regardless of player count. Fully live, 20 exchanges/player/day: 100 players ≈ $0.28/day; 10k ≈ $28/day; 100k ≈ $280/day (plus ~$0.20/MTok cache reads if the system prompt is cached). Sonnet 5.5 is 20× that. So: batch + cache for everything shareable, Haiku live for the rest, Sonnet/Opus only in the offline generation/review step.

**TTS.** Mandarin neural TTS list prices: Azure standard neural ~$15/M chars (third-party quotes; Microsoft's page is JS-rendered) [unverified], OpenAI $15/$30, Google $4-30 with 1M free WaveNet chars/month, ElevenLabs $50-100, MiniMax speech-02-hd $100/M official ([MiniMax pricing](https://platform.minimax.io/docs/guides/pricing-paygo.md); [Inworld comparison](https://inworld.ai/resources/tts-api-pricing-comparison)). Watch byte-vs-character billing: Fish Audio bills per UTF-8 byte, so Chinese costs 3× the headline. 100k unique 20-char lines ≈ 2M chars ≈ $30 at Azure rates, once. Pre-render at batch time, store in R2, key by content hash, serve with zero egress (R2: 10 GB storage and 10M Class B reads free, $0.015/GB-month, $0.36/M reads after). Live TTS is only needed for live-generated lines; even then cache by text hash because learners repeat.

**Hosting.** The agent-built examples used Vercel + Supabase (idle game) or a plain static host. For this game: static client on Cloudflare Pages/Vercel, one Worker or small server for the live LLM proxy (never ship API keys in the client; rate-limit per user), Supabase or D1 for saves/progress, R2 for audio, a nightly cron (GitHub Actions or a Worker cron) that runs the batch generation + validation + TTS. Cloudflare Workers AI has prompt caching for cached-input discounts ([docs](https://developers.cloudflare.com/workers-ai/features/prompt-caching/)). Fly is the fallback if a persistent process (e.g. jieba, review queue) is needed.

## 6. Is web-first actually "scalable" distribution?

**Evidence for web.** Poki 100M+ MAU (own figure), CrazyGames ~50M (company post), Ahrefs estimates 122M and 61M monthly visits respectively ([cbinsights](https://www.cbinsights.com/company/crazy-games); [indiegamebusiness](https://indiegamebusiness.com/web-gaming-for-indie-developers/)) [secondary]. 62% of web gamers later download or buy a game they met on web; 74% of surveyed devs call web publishing easy; 53% plan to port mobile games to web in 12 months ([Poki 2026 report](https://poki.com/blog/state-of-web-gaming-report-2026); [PDF](https://hub.poki-cdn.com/The_2026_State_of_Web_Gaming_Report_4ee6fdc260.pdf)). HTML5 releases nearly tripled YoY to ~15,000 in H1 2025 (Playgama via gamesindustry coverage) [secondary]. A URL has zero install friction, no 30% cut, instant updates, and the same build runs on phone and desktop.

**Evidence against treating web as the whole plan.** Web portals are ad-funded; Poki pays 100% on traffic you bring and 50/50 on portal traffic and asks for web exclusivity; CrazyGames ~60% ad share [unverified]; a "well-performing casual game" on a portal clears $200-2,000/month ([cinevva](https://app.cinevva.com/guides/web-game-monetization)) [secondary]. Players expect free, 11-20 minute sessions and quit at slow loads, which pushes toward small bundles (Defold ~1.1 MB gzipped vs Godot ~5-9 MB vs Phaser/Pixi a few hundred KB) [vendor table]. Portals want arcade loops, not a slow cozy learning game. Steam is where cozy games sell, but the 2025 median indie did ~$249 gross ([80.lv](https://80.lv/articles/analysts-report-drop-in-game-revenue-on-steam-despite-growing-number-of-releases); [Alinea: ~20k releases, indie 25% of revenue](https://gameworldobserver.com/2025/12/22/indie-projects-generated-a-quarter-of-the-total-game-revenue-on-steam-by-the-end-of-2025-analytics)). For language learning specifically, the only data found is vendor/secondary: consumer learning apps expect app-store discovery, working push (web push opt-in ~7% vs 42% native, weakly sourced) and offline ([winsome](https://winsomemarketing.com/edtech-marketing/multi-platform-strategy-for-learning-apps-when-to-build-web-vs.-mobile-first)) [unverified]. itch.io: 80% of paid games earn under $50/month [secondary].

**Honest read.** For a cozy edu game, web-first wins on *cost to reach a player* and *iteration speed*, not on *monetization*. Its real value is as the top of the funnel (shareable URL, playable demo, classroom and Discord links) and as a wrapper-ready base: a DOM/canvas build can later ship via Capacitor to the app stores and via Electron/Tauri to Steam, while a Godot GDScript build can go web + native but only without C#. The reverse (Steam-first native, web later) is the expensive direction. Pick web, design for a 2-3 MB first load, and treat Steam/app stores as later packaging of the same code.

## Why

[[decisions/0004-hospital-opening]] needs the opening as schema-validated content, pre-segmented and voiced like every other line, with the English bound checked in code instead of only in the decision. `contentSchema` is a strict object today, so the opening needs its own field and cast. This ticket is PR 0050 in the plan `docs/plans/hospital-opening.md` (section PR 0050).

## Done when

- [x] `contentSchema` and the `Content` type in `src/content/index.ts` gain an `opening` field.
- [x] A `castSchema` `{id, name, voiceId(s)}` describes the four speakers (王医生, the nurse, 老爷爷, 小姨). It is separate from `characterSchema`, which requires the accessory enum.
- [x] The step union has the types `say-en`, `say`, `request`, `reply` and `end`. Each step declares a `recover` list of the words it recovers.
- [x] Chinese steps reuse `Line`, pre-segmented into tokens with audio. `say-en` steps carry a plain `en` string and an `audio` path, and the token renderer never receives them.
- [x] A `superRefine` requires every `say-en` step to come before the first Chinese step.
- [x] A content test asserts that no Latin text appears anywhere in content outside `say-en` steps.
- [x] Variant A from `spikes/hospital-opening/content.js` is the script. Punctuation is folded into the line text, not tokens, because `wordSchema` (`:20-26`) allows only Han characters.
- [x] Opening tokens reuse the existing Word objects where a word already exists (来 bring, 想 think, 个 piece, 呀 ha). The 22 new words get dictionary entries (the plan corrected 23 to 22). The foods are 豆浆, 鸡蛋 and 馒头 from `content.foods`.
- [x] `src/content/words.ts:3-11` `contentWords` and the duplicate list in `src/content/content.test.ts:8-11` both include the opening.
- [x] Every opening line and every new word has a clip generated by the 0049 pipeline, listed in `public/audio/manifest.json`. A clip that fails generation blocks the PR.
- [x] Unit tests: the schema rejects a `say-en` step after a Chinese step; the Latin test fails on a planted English token; equal word ids are identical Word objects (`content.test.ts:140`); the manifest test covers the new clips.
- [x] `pnpm test` and `pnpm build` are green. The game plays as before, because nothing renders the opening yet.
- [ ] Live check: listen to every new line and word clip and confirm in the PR that each one says its text. Open day 1 in the preview and confirm it is unchanged.
- [ ] Perf budget: built JS grows by no more than 15 kB (baseline 401 kB). The PR states the total size of the added WAVs.

### What was learned

- `contentWords` now feeds lookups and the journal, so opening words journal through `reduceGame` with no rules change. The journal lists restaurant words first.
- A phrase's `text` keeps punctuation for speech while tokens stay Han-only, so `wordSchema` did not change. The pipeline speaks `text`, so its prosody follows the punctuation.
- Quiet word takes pass the pipeline: 吗 has peak 0.059 and RMS 0.014, and 担心 has RMS 0.0096. `wordVoice` is unlevelled, so these are worth hearing first.
- `game.test.ts` builds its own `Content`, so it gained an empty `opening`.
- `to-content.mjs` resets new audio paths to `/audio/pending.wav`. Rerun the pipeline with `--write-content` after it, and cached clips refill the paths without synthesis.
